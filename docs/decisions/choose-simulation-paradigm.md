# Choose simulation paradigm

- Date: 2026-09-18
- Decision: Use Discrete-Event Simulation (DES) as the primary simulation paradigm

## Context

Previous versions of the project were explicitly presented as Agent Based Models (ABM).

In those formulations, aircraft were described as autonomous agents and airports as the environment in which those agents interacted.

Implementations were developed in Arena and represented aircraft as entities moving through airport-specific processes.

The current project revisits those models with a different scope and implementation architecture.

The main phenomena of interest are:

- flight arrivals and departures;
- airport operations;
- operational delays;
- airport capacity;
- queues;
- flight travel times;
- disruptions; and
- flight redirection.

These phenomena are naturally represented through events, resources, queues and state changes occurring over simulation time.

## Decision

The current project will initially be formulated as a Discrete-Event Simulation (DES).

Flights will be represented as entities/processes moving through a network of airports, while airport capacity and operational constraints will be represented through simulation resources and events.

The model will focus on the temporal evolution of the system and the interactions generated by capacity and operational constraints.

## Rationale

DES provides a direct representation of the main mechanisms under study:

- events occur at specific points in simulated time;
- airport capacity can be represented through finite resources;
- aircraft waiting can be represented through queues;
- operational delays can be modeled as time-consuming processes;
- disruptions can change resource availability or routing rules.

The decision also fits the use of SimPy, which provides primitives for processes, events, resources and shared-capacity constraints.

The current implementation can be extended toward a hybrid or more explicit agent-based formulation if future requirements make individual aircraft behavior, autonomous decision-making or heterogeneous entities central to the research questions.

## Consequences

### Positive

- Clear representation of queues and capacity constraints.
- Natural modeling of operational events and delays.
- Direct compatibility with SimPy.
- Separation between system state and event scheduling.
- Suitable basis for reproducible scenario experiments.

### Negative

- Individual autonomous aircraft behavior is not the primary abstraction.
- Airline-specific behavior and detailed fleet decisions are outside the initial scope.
- A more detailed agent-based formulation may be required if future research questions depend on individual decision-making.

## Alternatives considered

### Agent-Based Modeling

Considered because the previous projects used this formulation.

It remains a possible extension if autonomous behavior and heterogeneous agents become central to the model.

### Hybrid DES/ABM

Could combine event-driven infrastructure with autonomous aircraft behavior.

It is not adopted initially because the current research questions can be addressed without introducing the additional complexity.
